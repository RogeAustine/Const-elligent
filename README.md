## 一、30 秒看懂这是什么

打开 `index.html`，输入一句现场目标，例如：

> C3 栋 15 层 MiC 模块吊装进度滞后，请判断偏差来源、给出可执行的抢工或顺延方案，并确认吊装窗口内的安全条件。

按下「启动多智能体编排」，系统会**当场**完成下面这条链路：

```
现场目标
   │
   ├─ 调度中枢拆解目标 ──→ 3 个带依赖关系的任务
   │
   ├─ [施工调度智能体] 并行执行 ──→ 查规范 → 算进度偏差 → 排塔吊窗口 → 推演方案 → 查吊装风险
   ├─ [安全巡检智能体] 并行执行 ──→ 查规范 → 融合视频AI与人员定位 → 生成整改工单
   └─ [设计智审智能体] 并行执行 ──→ 查规范 → 校核模块合规 → 检机电碰撞 → 给拆分建议
   │
   ├─ 系统检出跨域冲突（抢工会压缩安全监护窗口）
   │
   └─ 调度中枢汇总 ──→ 四段式决策建议 + 建议动作清单 + 需人工确认事项 + 证据台账
```

界面上同时可见：**编排依赖图**（任务在被拆开、被并行、被汇总）、**推理轨迹**（每一步 thought / action / observation 与工具真实返回值）、**数字孪生态势**（智能体每次判断落在哪个构件上并高亮）、**综合决策报告**。

**没有网络也能完整跑通** —— 默认使用内置的确定性推理器，不依赖任何外部服务、不需要 API Key。

## 二、怎么运行

### 方式一：双击打开

直接用 Chrome / Edge 打开 `index.html`。无需安装、无需联网、无需构建。

### 方式二：起一个本地服务

```bash
node tools/serve.js --port 8080
# 本机    http://127.0.0.1:8080/
# 局域网  http://<你的内网IP>:8080/   同一 WiFi 下手机可打开
```

### 方式三：接真实大模型

三种做法，任选其一：

1. **页面内设置**：右上角「设置」→ 选预设（DeepSeek / 通义千问 / 智谱 GLM / Anthropic）→ 填 API Key → 「测试连通性」→ 保存。
   密钥只存在本机 `localStorage`，不会上传到任何地方。
   > 注意：浏览器直连第三方接口会暴露密钥，且可能被 CORS 拦截，仅适合个人调试。
2. **本地网关（推荐线上部署）**：
   ```bash
   node gateway/server.js --port 8787 \
        --upstream https://api.deepseek.com/v1 \
        --model deepseek-chat \
        --key sk-你的密钥
   ```
   然后页面「设置」里选「本地网关 / vLLM」，Base URL 填 `http://127.0.0.1:8787/v1`，**不要填 API Key**。
   网关会把每次调用写进 `gateway/audit.log`，可事后复核"智能体当时看到了什么"。
3. **本地 vLLM / Ollama**：同上，`--upstream` 指向本机推理服务即可，无需密钥。

> 三种模式下**推理协议完全一致**：模型只负责"说什么、调哪个工具"，全部数值判定由工具层完成。
> 因此离线与在线两条路径的结论结构相同，演示可复现。

### 跑测试

```bash
npm test          # 核心契约测试 + 无头 UI 冒烟测试
npm run test:core # 75 个核心契约测试
npm run test:ui   # 30 个无头 UI 冒烟测试
```

零依赖：不需要 `npm install`，只用 Node 内置模块。

## 三、为什么这必须是"多智能体"

| | 单一大模型 | 见仁建智 |
|---|---|---|
| 专业边界 | 一段提示词里塞所有规范 | 四个智能体各有**工具白名单**，越权调用在引擎层被拒绝 |
| 判定口径 | 让模型自己"记住"阈值 | 阈值只写在**工具层**，提示词里根本不出现（有测试断言这一点） |
| 结论出处 | 模型自由发挥 | 每条结论都带 `cites`（规范号+条款+版本），**从工具返回值自动汇聚**，无法绕过 |
| 跨域冲突 | 在长上下文里自行妥协 | 由**确定性规则**（`IX-*`）检出并显式摆到台面上 |
| 可追溯 | 只有一个最终答案 | 完整轨迹：谁在第几步调了什么工具、拿到什么数据、得出什么结论 |
| 失败降级 | 模型一挂就白屏 | 三段降级：单智能体失败 → 该域标注不完整；规划失败 → 确定性模板；汇总失败 → 确定性综合 |

四个域不是随便切的，它们**互相约束**，这正是必须显式编排的理由：

- 施工调度要抢工 → 抬高安全风险（`IX-LIFT-SAFETY`）
- 设计要拆模块减重 → 走变更流程，反噬已经滞后的关键路径（`IX-DESIGN-SCHEDULE`）
- 绿能想夜间清洗 → 与高处作业/夜间作业风险叠加（`IX-ENERGY-SAFETY`）
- 塔吊与土方扬尘 → 是光伏积灰的直接来源，清洗周期应与扬尘作业计划联动（`IX-DESIGN-ENERGY`）

```
│    twin.js    数字孪生态势（模块状态 / 塔吊工况 / 组串健康度 / 缺陷台账）   │
│    canvas.js  多智能体编排画布（拓扑分层 + 依赖门控 + 实时脉冲）            │
│    trace.js   推理轨迹 · 证据台账 · 运行指标                                │
│    report.js  综合决策报告（四段结论 + 建议动作 + 人工确认 + 导出）         │
│    render.js  14 个工具结果渲染器（把工具 data 画成工程人员能读的证据卡）   │
├──────────────────────────────────────────────────────────────────────────┤
│  编排层  js/core/orchestrator.js                                          │
│    目标 → 任务图 → 拓扑分层 → 依赖门控并行分派 → 跨域关联 → 汇总           │

├──────────────────────────────────────────────────────────────────────────┤
│  运行引擎  js/core/agent.js  （唯一的 ReAct 闭环，四个智能体共用）          │
│    thought → action → observation 循环                                    │
│    工具白名单强制 · 证据自动汇聚 · 重复调用守卫 · 步数上限 · 异常降级       │
├──────────────────────────────────────────────────────────────────────────┤
│  角色与提示  js/core/prompts.js                                           │
│    4 个专业智能体 + 调度中枢：使命 / 边界 / 交付物 / 工具白名单 / 输出协议  │
├──────────────────────────────────────────────────────────────────────────┤
│  决策核心  js/core/llm.js                                                 │
│    适配器：offline（确定性推理，无网络可跑）/ openai / anthropic            │
│    ReAct 输出解析：容忍代码块、前后噪声、参数换名、嵌套括号                 │
├──────────────────────────────────────────────────────────────────────────┤
│  工具层  js/core/tools.js  （Agent 唯一能对世界产生副作用的地方）           │
│    设计：mic_check_compliance · bim_clash_detect · mic_suggest_split       │
│    施工：schedule_predict · crane_plan · safety_check_lift                 │
│    安全：safety_multimodal_scan                                            │
│    运维：bipv_diagnose · bipv_work_order                                   │
│    协同：kb_search(GraphRAG) · defect_list · dispatch_order · simulate_plan │
│    统一契约：{ ok, tool, data, cites, summary, error }                     │
├──────────────────────────────────────────────────────────────────────────┤
│  数据平台  js/data/                                                       │
│    project.js    MiC 模块 / C-SMART 传感器 / 工序计划 / 资源 / BIPV / 安全  │
│    knowledge.js  知识图谱（规范条文·故障模式·处置经验 + 关系边 + 文本块）   │
└──────────────────────────────────────────────────────────────────────────┘
```

**关键设计取舍**

1. **判定规则不写在提示词里。** 模型看不到阈值，就无法"顺着阈值编一个数"；阈值只存在于工具层，改规则不会让提示词失真。有测试断言提示词中不出现任何阈值。
2. **工具返回自带来处。** 每个工具返回 `cites`，Agent 的证据集合由工具返回值自动汇聚，模型无法凭空创造出处。
3. **数值只算一次。** 离线与在线两种模式调用的是同一批工具，因此同一问题在两种模式下结论一致，可复现。
4. **编排逻辑不交给模型。** 模型负责"拆得合理"和"说得清楚"，流程（分层、门控、汇总）是确定性的，任何一步失败都能定位到具体域。
5. **三层降级保证演示不中断。** 单智能体模型异常 → 保留已有证据并标注不完整；规划失败 → 确定性任务模板；汇总失败/过短 → 确定性四段综合。

## 六、测试

| 套件 | 用例数 | 覆盖什么 |
|---|---|---|
| `tests/run-tests.js` | 75 | 工具契约一致性、工程判定正确性（含阈值边界与误报）、知识检索出处、ReAct 解析容错、单智能体闭环、多智能体编排与依赖门控、提示词约束、数据自洽性 |
| `tests/dom-smoke.js` | 30 | 脚本加载与顺序、挂载点完整性、样式类名齐全、应用启动、全链路渲染、交互并发保护、设置持久化、**模型不可达时的降级不白屏** |

两个套件都零依赖。`dom-smoke.js` 自带一个约 200 行的 DOM 垫片，刻意不引入 jsdom —— 交付物要能断网双击运行，测试依赖也应保持零安装。

测试跑出来的都是真实缺陷，例如：

- `parseAction` 的参数回退链把 `{"action":...}` 本身当成了工具参数（工具拿到空参数）
- 进度外推用日均产能线性外推，未开工工序给出 196 天的荒谬延期
- 单串积灰 11% 的损失被错误归因到全场级"逆变器过温"上
- 塔吊排程未按日过滤，把别的日子的可用窗口算进了当天结论
- 测试运行器没有 await 异步用例，失败变成 unhandledRejection —— 报告显示"全部通过"而进程非零退出
- `createLLM` 的重试包装让失败落在无人接管的 Promise 链上，模型不可达时整份报告不渲染
- `report.js` 一处括号不匹配导致语法错误，页面完全打不开
