# 见仁建智 绿能运维 Agent

基于“海之子”大赛科技方向与项目申报书独立实现的第一版智能体，聚焦 BIPV 运维。给定设备遥测与检查任务，系统完成数据核验、偏差计算、知识检索和处置草案生成；人工确认后创建本地工单，再用新数据复测并决定是否关闭。

## 启动

需要 Python 3.10 或以上版本。后端仅使用标准库，前端不依赖 npm、CDN 或在线字体，默认模式无需账号、密钥或安装依赖。

在本目录双击 `start.bat`，或在终端执行：

```powershell
python app.py
```

打开 <http://127.0.0.1:8765>。程序只监听本机地址。终端按 Ctrl+C 停止；如果端口被占用，执行 `python app.py --port 8766` 并打开相应地址。

## 立即体验

1. 保持“局部发电异常”场景，点击“开始检查”。正常结果是发现 PV-03 发电偏低、PV-06 转换侧比值偏低，生成两份待确认草案。
2. 展开工具记录、原始样本和运维依据，查看判断来源；可以导出 Markdown 检查报告。
3. 确认一份草案，填写演示角色名称，进入“处置工单”。点击“模拟恢复并复测”，查看三条模拟恢复样本与关闭记录。
4. 切换“阴云经过”并重新检查。绝对功率下降，但归一化后不生成维修草案。
5. 切换“低辐照观察”：由于证据不足，设备进入观察状态，不生成维修草案。

模拟复测仅验证软件流程。主页继续显示原始数据集快照，不会把历史异常数据改写成恢复数据；恢复证据保存在工单内。

## 已实现的能力

- 单个绿能运维 Agent：限定任务范围，按本地工具流程执行并保留每步输入摘要、结果、时间与数据指纹。
- 归一化性能计算、连续异常检测、观测不足与过期样本处理。
- 按异常类型检索本地手册，保留 KB 编号、出处与使用边界。
- 人工审批、重复工单拦截、通过或未通过的复测记录、工单状态持久化。
- CSV 导入、图表、设备证据、历史检查、检查报告与工单 JSON 导出。
- 可选兼容 Chat Completions 协议的大模型辅助解释；失败时保留已完成的本地结果。

默认是**规则驱动的工具型 Agent**。自然语言任务支持全站检查和 `PV-03` 这样的设备编号限定，其他表述保留为检查目标，不具有通用自然语言规划能力。大模型接入负责补充解释，不改变数值判断、审批或工单状态。界面会明确展示当前模式。

本版本没有实现申报书中的模型微调、GraphRAG、多智能体协同、BIM 数字孪生或真实 C-SMART 对接。知识检索是结构化精确匹配，不包装成 GraphRAG；不会凭功率数据直接确诊热斑或设备损坏。

## 导入数据

点击“导入 CSV”，或先下载页面上的 96 行模拟模板。`examples/inspection.csv` 和 `examples/retest.csv` 是一组可验证的异常与恢复样例，均为合成数据。

| 列名 | 含义 | 要求 |
|---|---|---|
| timestamp | 项目当地采样时间 | ISO 格式；不带时区，例如 `2026-09-20T10:00:00` |
| device_id | 监测单元编号 | 非空，同一时刻同一设备不可重复 |
| irradiance_wm2 | 组件平面的辐照 | W/m²，0–1600 |
| module_temp_c | 组件温度 | °C，−40–110 |
| dc_power_w | 监测单元直流功率 | W，非负 |
| ac_power_w | 同一范围交流功率 | W，非负，不能高于直流功率超过 2 W |
| rated_power_w | 对应额定直流功率 | W，大于 0，同一设备保持一致 |

文件须为 UTF-8，可带 BOM；最多 2 MB、5000 行、100 台设备。一行的 AC/DC 必须对应同一监测范围，组件与集中式逆变器不能未经映射直接比较。一次检查针对一个数据集。

复测数据需包含目标设备至少三条记录，全部晚于原异常时间，额定功率保持一致。上传数据产生的工单不能用内置模拟恢复按钮关闭。

## 规则与假设

- 参考直流功率：额定功率 × 辐照 / 1000 × `[1 − 0.0035 × (组件温度 − 25)]`。
- 参考交流功率：参考直流功率 × 0.96。
- 最近三个样本的相邻间隔不超过 30 分钟，辐照均不低于 200 W/m²，才进入持续偏差判断。
- 连续三个样本归一化直流功率低于 78%：产生局部发电偏低草案。
- 连续三个样本直流功率大于 20 W，且 AC/DC 比值低于 87%：产生转换侧复核草案。
- 若两项同时发生，优先报告转换侧偏差；单次偏差进入观察。
- 设备记录落后于该批次最新记录超过 30 分钟时进入观察。时效判断相对数据批次，允许历史数据回放。

以上系数与阈值都是**演示假设**，不是行业规范或厂商结论。现场使用前需要真实设备参数、测点映射、历史基线、专业运维校准与效果验证。

## 可选模型配置

默认不调用任何外部模型。若需要模型解释，在启动前设置环境变量：

```powershell
$env:AGENT_MODEL_ENDPOINT = 'https://你的服务商地址/v1/chat/completions'
$env:AGENT_MODEL_NAME = '你的模型名称'
$env:AGENT_MODEL_KEY = '你的密钥'
python app.py
```

地址必须是完整的 Chat Completions 接口。远程地址必须使用 HTTPS；本机模型允许 HTTP。密钥仅从环境变量读取，不进入浏览器或数据库。请求仅发送任务、偏差指标摘要和匹配手册，不发送整份 CSV。模型输出属于待复核解释，不能改变工单状态。是否启用、模型调用失败等状态均在页面显示。

本交付未使用真实账号调用外部模型。实际接口兼容性需配置后验证。提供方协议、配额和上下文长度由你选择的模型服务决定。

## 验证

```powershell
python -m unittest discover -s tests -v
node --check web/app.js
```

Node 仅用于开发时的 JavaScript 语法检查，运行应用不需要 Node。测试使用独立临时数据库，不读取或修改你的项目资料。`docs/validation.md` 记录本次验证结果。
