# 四分钟演示脚本

## 0:00 至 0:30 场景与定位

打开工作台，说明项目是“见仁建智”中的绿能运维 Agent，归属科技方向。当前演示使用 8 个合成监测单元的数据，不声称已接入真实电站。

目标：让项目运维人员从“看到发电下降”走到“有依据的处置与复测”。

## 0:30 至 1:30 真实执行检查

选择“局部发电异常”，点击“开始检查”。查看五条工具记录：确定范围、读取遥测、归一化计算、检索手册、生成草案。

展示 PV-03 的归一化直流功率偏低、PV-06 的转换比值偏低。展开一份草案的三个原始采样点和 KB 引用。强调这是待核验原因，不凭少量功率数据确诊具体硬件损坏。

## 1:30 至 2:30 人工确认与闭环

确认 PV-03 草案，填写“演示运维员”。打开“处置工单”，展示新建工单。点击“模拟恢复并复测”，展示“复测通过 · 已关闭”和操作记录。

明确复测为模拟恢复数据，只证明软件闭环可运行。原始异常批次仍保留，复测记录单独存档。

## 2:30 至 3:15 控制误报

切换“阴云经过”并开始检查：全站绝对功率下降，但天气归一化后无需维修。

切换“低辐照观察”：证据不足，系统选择观察而不是生成工单。说明处置并非每次都要派单。

## 3:15 至 4:00 可追溯交付

展示历史检查、导出报告、CSV 模板和一页架构图。说明当前本地规则驱动模式可离线运行，模型接口是可选解释能力。

结束时说明下一阶段接入真实数据与手册后，需要标定设备参数、评估误报漏报，再讨论模型规划或与现有平台集成。

## 演示前准备

运行测试，启动本地服务，打开页面。检查端口没有被旧实例占用。若已有同设备未关闭工单，先在工单页完成模拟复测，或直接展示已有工单；程序会拦截重复创建。
